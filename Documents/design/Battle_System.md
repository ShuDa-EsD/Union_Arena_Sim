# Union Arena 战斗系统设计文档

> 本文档详细描述 Union Arena 的攻击阶段流程、战斗结算、伤害计算与状态变化。
> 基于官方规则手册 Ver1.1，为规则引擎的战斗模块提供精确的设计蓝图。

---

## 一、战斗系统概览

### 1.1 战斗发生时机

战斗**仅在 Attack Phase（攻击阶段）**发生。玩家在 Main Phase 完成后可选择进入 Attack Phase。

### 1.2 战斗参与者

| 角色 | 说明 |
|------|------|
| 攻击方 (Attacker) | 当前回合玩家 |
| 防御方 (Defender) | 非回合玩家 |
| 攻击角色 | 攻击方前线上的 1 个 Active 角色 |
| 阻挡角色 | 防御方前线上的 1 个 Active 角色（可选） |
| 攻击目标 | 对手玩家（默认）或对手前线角色（Snipe） |

### 1.3 核心规则约束

- 攻击角色必须是 **Active** 状态
- 攻击宣言时，攻击角色 **立即切换为 Resting**
- 每次只能有 1 个角色进行攻击
- 攻击**不消耗 AP**
- 攻击阶段中**不能使用卡牌**（但 Trigger 能力可以发动 — RQ-007 确认：Trigger 不算"使用卡牌"）
- 可以连续攻击多次（只要有 Active 角色剩余）
- 不进行攻击则攻击阶段**立即结束**

**关于"召唤失调"（RQ-002 确认）**：
> Union Arena **不存在**类似 MTG 的召唤失调规则。角色能否攻击仅取决于：
> 1. 是否在**前线**
> 2. 是否为 **Active** 状态
> 3. 当前是否为 **Attack Phase**
>
> 由于角色打出时默认 **Resting**，当回合打出的角色无法攻击（因为非 Active）。Raid 入场会将角色切换为 Active，因此 Raid 入场角色**可以**立即攻击。任何效果若能将本回合入场的角色切换为 Active，该角色也可以攻击。
>
> 同样，Activate: Main 能力若需要 Switch to Resting 代价，只要该角色是 Active 状态即可发动，与入场回合无关。

## 二、攻击阶段完整流程

### 2.1 阶段状态机

```
                         ┌─────────────────┐
                         │  进入 Attack Phase │
                         └────────┬────────┘
                                  │
                    (无Active角色或选择不攻击)
                                  │
                         ┌────────▼────────┐
                         │   攻击阶段结束     │
                         └─────────────────┘
                                  │
                    (有Active角色且选择攻击)
                                  │
                                  ▼
              ┌────────────────────────────────────┐
              │        ① 攻击角色宣言                │
              │  • 选择前线1个Active角色             │
              │  • 切换为Resting                    │
              │  • 选择攻击目标（玩家 或 Snipe选角色）│
              │  • 触发 When Attacking 能力          │
              └────────────────┬───────────────────┘
                               │
                               ▼
              ┌────────────────────────────────────┐
              │        ② 阻挡角色宣言                │
              │  • 防御方选择是否阻挡                │
              │  • 阻挡：选前线1个Active角色→Resting  │
              │  • 触发 When Blocking 能力           │
              │  • Snipe攻击：不可阻挡               │
              └────────────────┬───────────────────┘
                               │
                               ▼
              ┌────────────────────────────────────┐
              │        ③ 攻击结算                   │
              │  (根据攻击目标走不同分支)             │
              └────────────────┬───────────────────┘
                               │
                               ▼
              ┌────────────────────────────────────┐
              │        ④ 战斗结束处理                │
              │  • 结算"战斗结束时"能力              │
              │  • 清除"本次战斗中"持续性效果        │
              └────────────────┬───────────────────┘
                               │
                               ▼
              ┌────────────────────────────────────┐
              │    还有Active角色且想继续攻击？       │
              │    YES → 回到①    NO → 阶段结束      │
              └────────────────────────────────────┘
```

## 三、攻击宣言 (Attack Declaration)

### 3.1 普通攻击（目标：对方玩家）

```
条件检查：
  ├─ 攻击角色是否在前线？       ✅ 必须
  ├─ 攻击角色是否为 Active？    ✅ 必须
  ├─ 攻击阶段中？              ✅ 必须
  └─ 是否存在阻止攻击的效果？    ❌ 如有则不可攻击

执行动作：
  1. 攻击角色 Active → Resting
  2. 记录攻击目标 = 对方玩家
  3. 触发 When Attacking 能力
```

### 3.2 Snipe 攻击（目标：对方前线角色）

```
额外能力：攻击角色拥有 Snipe 关键词

特殊规则：
  ├─ 攻击目标改为对方前线上的任意角色（Active/Resting均可）
  ├─ 目标角色的朝向不改变
  ├─ 防御方不能进行阻挡宣言
  ├─ 仍发生战斗（BP比较）
  └─ 目标角色不视为"阻挡"，不触发 When Blocking

注意：即使角色有"不能被选择(Chosen)"的保护能力，
      Snipe 仍然可以将其作为攻击目标。
     （Snipe的"选择"是攻击目标指定，不等同于能力"选择"）
```

### 3.3 When Attacking 能力触发

```
When Attacking 能力在攻击宣言后立即结算，在阻挡宣言之前。
```

## 四、阻挡宣言 (Block Declaration)

### 4.1 阻挡条件

```
条件检查：
  ├─ 攻击目标是否为玩家？        ✅ Snipe攻击不可阻挡
  ├─ 阻挡角色是否在前线？        ✅ 必须
  ├─ 阻挡角色是否为 Active？     ✅ 必须
  ├─ 防御方是否选择阻挡？        ✅ 可选
  └─ 是否存在阻止阻挡的效果？     ❌ 如有则不可阻挡

执行动作：
  1. 阻挡角色 Active → Resting
  2. 记录阻挡角色
  3. 触发 When Blocking 能力
```

### 4.2 不阻挡的情况

```
若防御方不选择阻挡：
  ├─ 攻击目标必定是玩家
  ├─ 触发攻击角色的"未被阻挡时"能力
  └─ 直接造成伤害（见第六节）
```

### 4.3 When Blocking 能力触发

```
When Blocking 能力在阻挡宣言后立即结算，在攻击结算之前。
注意：Snipe 攻击不经过阻挡步骤，因此不触发 When Blocking。
```

## 五、战斗结算 — 角色 vs 角色

### 5.1 BP 比较

```
发生条件：攻击目标为对方角色（包括Snipe和反击等情况）

比较方式：
  攻击角色 BP  vs  目标角色 BP

战斗不改变双方BP值（仅比较，不削减）
```

### 5.2 结算分支 A：攻击方 BP ≥ 目标 BP

```
结果：攻击方获胜

结算步骤：
  ┌─────────────────────────────────────────────┐
  │ ① 将目标角色 Sidelined（进入 Sideline）       │
  │    触发该角色的 When Sidelined 能力            │
  │    触发因该角色被Sidelined而发动的其他能力       │
  ├─────────────────────────────────────────────┤
  │ ② 结算攻击方的"战斗获胜时"能力                 │
  │    如 Impact 1 → 对对手造成 1 点额外伤害       │
  │    其他"攻击获胜时"能力                         │
  └─────────────────────────────────────────────┘
```

### 5.3 结算分支 B：攻击方 BP < 目标 BP

```
结果：攻击方战败

结算步骤：
  ┌─────────────────────────────────────────────┐
  │ ① 结算攻击方的"攻击战败时"能力                 │
  ├─────────────────────────────────────────────┤
  │ ② 结算防御方的"战斗获胜时"能力                 │
  └─────────────────────────────────────────────┘

重要：攻击方战败后不被 Sidelined，继续留在场上。
```

### 5.4 BP = 0 的特殊处理

```
当场上角色的 BP 因能力效果被降低至 0 或以下时：
  → 该角色立即被 Sidelined
  → 这是独立于战斗结算的规则
```

## 六、战斗结算 — 攻击对方玩家（直接伤害）

### 6.1 直接伤害流程

```
发生条件：攻击未被阻挡（目标始终是玩家）

伤害计算：
  ├─ 默认造成 1 点伤害
  ├─ 拥有 Damage 2 → 造成 2 点伤害
  └─ 拥有 Damage +1 → 伤害 +1（可叠加）

执行步骤：
  1. 确定伤害点数 N
  2. 攻击方从防御方生命区选择 N 张卡
  3. 防御方逐一翻开并检查 Trigger
  4. 若防御方生命区变为 0 → 攻击方胜利
```

### 6.2 伤害特性

| 伤害类型 | 来源 | 伤害值 | 说明 |
|---------|------|--------|------|
| 普通直接伤害 | 攻击未被阻挡 | 1 | 翻1张生命卡 |
| Damage 2 | 关键词 | 2 | 翻2张生命卡（同时翻开） |
| Damage +1 | 关键词 | +1 | 额外多翻1张（可叠加） |
| Impact 1 | 战斗获胜 | 1 | 额外伤害（不叠加） |
| Impact +1 | 关键词 | +1 | Impact伤害+1（无Impact时获得Impact 1） |

## 七、Trigger 检查系统

**RQ-007 确认**：Trigger 能力的发动**不算**"使用卡牌"（using a card）。因此即便在攻击阶段（规则禁止使用卡牌），Trigger 能力仍可正常发动。Trigger 是独立的游戏机制，不受 Attack Phase 的"Cards cannot be used"限制。

### 7.1 Trigger 检查流程

```
对于每一点伤害：
  ┌─────────────────────────────────────────────┐
  │ 1. 攻击方从被伤害方生命区选择 1 张卡           │
  ├─────────────────────────────────────────────┤
  │ 2. 被伤害方将该卡翻开（正面朝上）               │
  ├─────────────────────────────────────────────┤
  │ 3. 检查该卡是否有 Trigger 能力                 │
  │    ├─ 有 Trigger → 可选择是否发动             │
  │    │   └─ 选择发动 → 结算能力                 │
  │    └─ 无 Trigger → 跳过                      │
  ├─────────────────────────────────────────────┤
  │ 4. 该卡放入 Sideline（无论是否有Trigger）       │
  └─────────────────────────────────────────────┘
```

### 7.2 多点伤害的 Trigger 处理

```
Damage 2 造成 2 点伤害时：
  ├─ 攻击方一次选择 2 张生命卡
  ├─ 防御方同时翻开 2 张
  └─ 若都有 Trigger：
      ├─ 防御方选择发动顺序
      ├─ 逐一结算（第1张结算完 → Sideline → 再结算第2张）
      └─ 结算第1张时产生的新Trigger也加入队列
```

### 7.3 Trigger 能力特征

```
Trigger 是卡牌上独立的可选能力：
  ├─ 发动是可选的（Activation is optional）
  ├─ 在生命区被翻开时触发
  ├─ 无论卡牌类型（角色/Site/Event），Trigger都可能存在
  └─ 结算后该卡进入 Sideline
```

## 八、战斗相关关键词能力

### 8.1 关键词一览

| 关键词 | 类型 | 触发时机 | 效果 |
|-------|------|---------|------|
| **Snipe** | 攻击选择 | 攻击宣言时 | 可攻击对方前线角色，不可阻挡 |
| **Double Attack** | 攻击后 | 首次攻击后 | 该角色 Resting → Active（每回合1次） |
| **Double Block** | 阻挡后 | 首次阻挡后 | 该角色 Resting → Active（每回合1次） |
| **Impact 1** | 战斗获胜 | 攻击获胜时 | 对对手造成 1 点伤害（不叠加） |
| **Impact +1** | 战斗获胜 | 攻击获胜时 | Impact 伤害 +1（无 Impact 则获得 Impact 1） |
| **Damage 2** | 直接伤害 | 未被阻挡攻击时 | 造成 2 点直接伤害（不叠加） |
| **Damage +1** | 直接伤害 | 未被阻挡攻击时 | 直接伤害 +1（可叠加） |
| **Nullify Impact** | 战斗中 | 战斗期间 | 对方角色在此期间失去 Impact |

### 8.2 关键词结算优先级

```
战斗中的关键词结算顺序：
  1. Snipe（影响攻击目标选择，在攻击宣言时）
  2. Nullify Impact（战斗持续期间生效）
  3. Impact (战斗获胜后)
  4. Double Attack / Double Block（战斗结束后）
  5. Damage（直接攻击玩家时，代替默认1点伤害）
```

## 九、状态变化追踪

### 9.1 一次完整攻击中的状态变化

```
时间线：一次攻击从开始到结束的状态变化

  Attack Phase 开始
  │
  ├─ 选择攻击角色
  │   └─ 攻击角色: Active → Resting
  │
  ├─ 目标选择
  │   ├─ 普通攻击: target = Opponent Player
  │   └─ Snipe攻击: target = Opponent Front Line Character
  │
  ├─ When Attacking 能力触发 & 结算
  │
  ├─ [如有阻挡] 阻挡角色: Active → Resting
  │   └─ When Blocking 能力触发 & 结算
  │
  ├─ [No Block] 未阻挡时能力触发 & 结算
  │
  ├─ 战斗结算
  │   ├─ [角色vs角色] BP比较 → 胜负判定 → Sideline / Impact
  │   └─ [角色vs玩家] 伤害计算 → 翻生命卡 → Trigger检查
  │
  ├─ 战斗结束能力触发 & 结算
  │
  ├─ 清除"本次战斗中"持续性效果
  │
  └─ [如有Double Attack] 攻击角色: Resting → Active
```

### 9.2 状态变更分类

| 变更类型 | 触发源 | 可逆性 |
|---------|--------|--------|
| Active ↔ Resting | 攻击/阻挡宣言、Double Attack/Block | 可逆 |
| Front Line → Sideline | 战斗战败 | 不可逆 |
| 场上 → Sideline | BP降至0、效果 | 不可逆 |
| Life Area → Sideline | 受伤害 | 不可逆 |
| 手牌/场上 → Removal Area | 超限、满位 | 几乎不可逆 |

## 十、边界情况与规则细化

### 10.1 攻击方BP恰好等于目标BP

> 攻击方 BP ≥ 目标 BP → **攻击方获胜**。
> BP相等时走分支A，目标被Sidelined。

### 10.2 多个角色可攻击

> 只要有 Active 角色在前线，可以连续多次攻击。每次攻击完全结算后，再选择下一个攻击角色。

### 10.3 无Active角色时

> 如果 Attack Phase 开始时前线上没有 Active 角色，或玩家选择不攻击，Attack Phase **立即结束**。

### 10.4 阻挡角色被Sidelined后

> 如果在 When Blocking 结算过程中阻挡角色被移走（如自身能力 Sideline This Card），阻挡仍然成立，战斗按规则继续。

### 10.5 Impact + Damage 叠加

```
一个角色同时触发 Impact 和直接伤害时：

例：Snipe攻击角色 → 战斗获胜(Impact 1) → 对方受1点Impact伤害
    但这与攻击的直接伤害是分开结算的。

直接伤害（攻击未被阻挡时）和 Impact伤害（战斗获胜时）是不同的伤害来源。
```

## 十一、规则引擎战斗模块接口设计要点

### 11.1 核心接口需求

```
AttackManager:
  ├─ canAttack(characterId) → boolean
  ├─ declareAttack(characterId, targetType, targetId?) → AttackContext
  ├─ declareBlock(characterId) → BlockContext
  ├─ resolveBattle(attackContext) → BattleResult
  ├─ resolveDamage(playerId, damageAmount) → TriggerCheckResult
  ├─ resolveTrigger(cardId) → TriggerResult
  └─ endBattle(battleResult) → StateChanges
```

### 11.2 状态快照

```
每次战斗需要快照的状态：
  ├─ 攻击角色 BP 及时点快照（战斗中不变化，但需要原值比较）
  ├─ 目标角色 BP 快照
  ├─ 当前生效的持续性效果
  └─ 关键词能力列表
```

### 11.3 事件钩子

```
战斗系统需要抛出的事件：
  ├─ ON_ATTACK_DECLARED
  ├─ ON_BLOCK_DECLARED
  ├─ ON_BATTLE_START
  ├─ ON_BP_COMPARISON
  ├─ ON_BATTLE_WIN / ON_BATTLE_LOSE
  ├─ ON_CHARACTER_SIDELINED
  ├─ ON_DAMAGE_DEALT
  ├─ ON_TRIGGER_CHECK
  ├─ ON_TRIGGER_ACTIVATED
  └─ ON_BATTLE_END
```
