# Union Arena 游戏整体设计文档

> 本文档描述 Union Arena 数字版的游戏整体流程、玩家目标、胜利条件与回合结构。
> 基于官方规则手册 Ver1.1 设计，为规则引擎开发提供顶层架构参考。

---

## 一、游戏概览

### 1.1 游戏类型

- **类型**：双人对战集换式卡牌游戏 (Trading Card Game)
- **对战模式**：1v1
- **回合制**：双方交替进行回合

### 1.2 核心概念

每位玩家拥有一套 **50张卡牌** 组成的卡组与 **3张AP卡**。通过使用卡牌召唤角色、布置场地、发动能力，逐步削减对手的 **7点生命值** 至零以获取胜利。

### 1.3 核心资源

| 资源类型 | 说明 | 来源 |
|---------|------|------|
| 生命 (Life) | 初始7张卡，受到伤害时翻开 | 游戏开始时从卡组顶放置 |
| 手牌 (Hand) | 行动选择来源 | 每回合抽牌 + 额外抽牌 |
| 行动点 (AP) | 使用卡牌的消耗 | 每回合按规则自动补充 |
| 能量 (Energy) | 使用卡牌的颜色/数量需求 | 能量线上的卡牌提供 |
| 卡组 (Deck) | 抽牌来源，耗尽即危险 | 初始50张构筑卡组 |

## 二、玩家目标与胜利条件

### 2.1 玩家目标

通过策略性地使用卡牌、管理资源、控制场面，率先满足以下任一胜利条件。

### 2.2 胜利条件（满足其一即获胜）

#### 条件A：对手生命耗尽

> 对手的生命区没有任何卡牌剩余。

- 每次直接攻击玩家成功，造成 1 点伤害（翻1张生命卡）
- 拥有 Damage 2 的角色造成 2 点伤害（翻2张生命卡）
- 拥有 Impact 的角色战斗中获胜可额外造成伤害

#### 条件B：对手无法抽牌（牌库耗尽）

> 在对手的 Start Phase 中，当需要抽牌时对手的卡组中没有剩余卡牌。

- 仅在 Start Phase 的强制抽牌步骤检查
- 额外抽牌（支付1AP）步骤导致无法抽牌不算获胜

### 2.3 生命区机制

- 初始 **7张** 卡牌，从卡组顶背面朝下放置
- 受到伤害 → 攻击方选择对应数量的生命卡 → 被攻击方翻开并检查 Trigger
- Trigger 是可选发动的能力，结算后卡牌进入 Sideline
- 无 Trigger 的卡也进入 Sideline
- 多张 Trigger 由检查方**按任意顺序**逐一结算

## 三、游戏准备流程

```
┌─────────────────────────────────────┐
│ 1. 洗牌，将卡组放入 Deck Area        │
├─────────────────────────────────────┤
│ 2. 猜拳决定 Player One / Player Two │
├─────────────────────────────────────┤
│ 3. 各抽 7 张手牌                     │
├─────────────────────────────────────┤
│ 4. 调度 (Mulligan) — 可选一次        │
│    • 先手先决定是否调度               │
│    • 调度：手牌放回牌库底 → 重抽7张 → 洗牌 │
├─────────────────────────────────────┤
│ 5. 从卡组顶取 7 张，背面放入生命区    │
├─────────────────────────────────────┤
│ 6. Player One 开始第一回合            │
└─────────────────────────────────────┘
```

## 四、场地布局 (Field)

### 4.1 七区域定义

```
┌──────────────────────────────────────────────────────┐
│                    PLAYER A                          │
│                                                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐           │
│  │   Deck   │  │   AP     │  │   Life   │           │
│  │  (50张)  │  │  Area    │  │   Area   │           │
│  │  牌库区  │  │  (0-3张) │  │  (0-7张) │           │
│  └──────────┘  └──────────┘  └──────────┘           │
│                                                      │
│  ┌────────────────────────────────────────┐          │
│  │         Front Line (前线, 最多4)        │          │
│  │   放置角色卡，用于攻击和阻挡              │          │
│  └────────────────────────────────────────┘          │
│  ┌────────────────────────────────────────┐          │
│  │        Energy Line (能量线, 最多4)       │          │
│  │   放置角色卡/Site卡，提供能量生成          │          │
│  └────────────────────────────────────────┘          │
│                                                      │
│  ┌──────────────┐  ┌──────────────┐                  │
│  │   Sideline   │  │   Removal    │                  │
│  │   (Sideline) │  │    Area      │                  │
│  │   公开弃牌区  │  │   (永久移除)  │                  │
│  └──────────────┘  └──────────────┘                  │
│                                                      │
│                     HAND                             │
└──────────────────────────────────────────────────────┘
```

### 4.2 区域规则

| 区域 | 容量限制 | 可见性 | 卡牌类型限制 | 说明 |
|------|---------|--------|-------------|------|
| Deck Area | 无（初始50张） | 背面/仅自己 | 全部 | 洗牌后不可查看 |
| Hand | 上限8张（End Phase检查） | 仅自己 | 全部 | 超出则弃入Removal Area |
| Front Line | 4张 | 公开 | 仅角色卡 | 用于攻击和阻挡 |
| Energy Line | 4张 | 公开 | 角色卡+Site卡 | 提供能量生成 |
| Life Area | 初始7张 | 背面/仅自己 | 全部 | 受到伤害时翻开 |
| AP Area | 0-3张 | 公开 | 仅AP卡 | 支付AP时Resting |
| Sideline | 无限制 | 公开/正面 | 全部 | 卡牌被Sidelined或使用后 |
| Removal Area | 无限制 | 公开/正面 | 全部 | 永久移除，不可恢复 |

### 4.3 区域联动关系

```
Front Line + Energy Line = Field (场上)

能量线上卡牌 → 产生能量 → 使用手牌中的卡牌
前线上角色卡 → 攻击/阻挡 → 消耗对手生命/保护自身
场上卡牌    → 发动能力  → 影响游戏状态
```

## 五、卡组构筑规则

### 5.1 卡组构成

| 规则 | 说明 |
|------|------|
| 卡组总数 | 精确 **50张** |
| AP卡 | 固定 **3张**，不占卡组位置 |
| 来源代码 | 全部50张必须拥有**相同的来源材料代码**（卡号前3位字母） |
| 同名限制 | 相同卡号**最多4张** |
| SPECIAL/FINAL限制 | 每种Trigger类型合计**最多4张** |

### 5.2 示例

> 使用 `UA03BT/HTR-1-001` → 可放最多4张卡号为 `HTR-1-001` 的卡
> 且全部50张卡号前3位必须为 `HTR`

## 六、卡牌状态系统

### 6.1 Active 与 Resting

卡牌在场上只有两种朝向状态：

| 状态 | 朝向 | 能否攻击 | 能否阻挡 | 能否发动 Activate 能力 |
|------|------|---------|---------|----------------------|
| Active | 竖放 (Vertical) | ✅ | ✅ | 需要 Switch to Resting 的能力可以 |
| Resting | 横放 (Horizontal) | ❌ | ❌ | 不能支付"Switch to Resting"代价 |

### 6.2 状态切换时机

```
打出卡牌时       → Resting
Start Phase     → 全部 Resting → Active
End Phase       → 全部 Resting → Active (不含AP卡)
攻击宣言时       → Active → Resting
阻挡宣言时       → Active → Resting
支付AP时         → Active AP → Resting AP
能力代价         → 按要求切换
```

## 七、AP系统

### 7.1 AP卡数量变化表

|  | Turn 1 | Turn 2 | Turn 3+ |
|--|--------|--------|---------|
| Player One（先手） | 1张 | 2张 | 3张 |
| Player Two（后手） | 2张 | 2张 | 3张 |

- 第3回合起双方均为3张AP卡
- 新AP卡放置时默认为 **Active** 状态
- 每回合 Start Phase 中自动调整至表内数量

### 7.2 AP使用规则

- 支付1AP = 将1张 Active AP卡 → Resting
- 使用卡牌前检查 AP Cost 是否可支付
- 每回合 Start Phase 可支付1AP进行额外抽牌（每回合限1次）

## 八、回合结构 (Turn Structure)

### 8.1 回合状态机

```
                    ┌──────────┐
                    │ 游戏开始  │
                    └────┬─────┘
                         │
                         ▼
              ┌──────────────────┐
         ┌───→│  Player One Turn │
         │    └────────┬─────────┘
         │             │
         │             ▼
         │    ┌──────────────────┐
         └────│  Player Two Turn │
              └────────┬─────────┘
                       │
            (循环直至胜利条件满足)
```

### 8.2 单回合详细流程

```
┌─────────────────────────────────────────────────────────────┐
│                    TURN STRUCTURE                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ① START PHASE（开始阶段）                                    │
│     ├─ 清除"到本回合开始为止"的持续性能力                        │
│     ├─ 全部Resting卡 → Active (角色/Site/AP)                  │
│     ├─ 按AP表调整AP卡数量（新AP卡设为Active）                    │
│     ├─ 抽1张卡（先手第1回合跳过）                                │
│     └─ 可选：支付1AP额外抽1张（每回合1次，先手第1回合可用）         │
│                                                             │
│  ② MOVEMENT PHASE（移动阶段）                                  │
│     ├─ 可将任意数量角色从能量线 → 前线（同时进行）                 │
│     ├─ • 目标满4张时：为每个要移入的角色移除目标线1张卡             │
│     ├─ • Step关键词：允许前线 → 能量线逆向移动                    │
│     ├─ • 逆向移动目标满时：可选择交换位置（而非移除）               │
│     └─ • Site卡不可移动                                       │
│                                                             │
│  ③ MAIN PHASE（主要阶段）                                     │
│     ├─ A: 使用手牌中的卡（需满足能量+支付AP）                     │
│     │    ├─ 打出角色卡 → 前线或能量线 (Resting)                  │
│     │    ├─ Raid打出角色卡 → 堆叠在指定角色上                    │
│     │    ├─ 打出Site卡 → 仅能量线 (Resting)                     │
│     │    └─ 使用Event卡 → 结算能力 → 进入Sideline               │
│     │                                                        │
│     └─ B: 发动场上卡的 Activate: Main 能力                     │
│          └─ 满足条件即可发动，Once Per Turn每张卡各1次            │
│                                                             │
│  ④ ATTACK PHASE（攻击阶段）                                    │
│     └─ (详见 Battle_System.md)                                │
│                                                             │
│  ⑤ END PHASE（结束阶段）                                       │
│     ├─ 激活并结算"End Phase开始时"能力                           │
│     ├─ 全部Resting角色/Site → Active (AP卡保持Resting)          │
│     ├─ 手牌上限检查：超过8张时选择8张保留，其余 → Removal Area     │
│     └─ 清除"本回合结束为止"的持续性能力                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 8.3 各阶段能力发动权限

| 阶段 | 使用卡牌 | 发动 Activate: Main | 攻击 |
|------|---------|---------------------|------|
| Start Phase | ❌ | ❌ | ❌ |
| Movement Phase | ❌ | ❌ | ❌ |
| Main Phase | ✅ | ✅ | ❌ |
| Attack Phase | ❌ | ❌ | ✅ |
| End Phase | ❌ | ❌ | ❌ |

## 九、关键概念速查

### 9.1 Raid（叠加召唤）

- 角色卡可选择以 Raid 方式打出（如果卡上标注 Raid）
- 将新卡**堆叠**在指定的已有角色卡上方
- 效果：切换为Active → 可移至前线 → When Played 能力激活
- 底部卡的能力失效
- Raid 与普通打出共享能量/AP条件

### 9.2 Trigger（生命触发）

- 生命卡被翻开时检查
- 可选发动
- 多张 Trigger 按**任意顺序**逐一结算
- 每张结算后放入 Sideline

### 9.3 Sideline（公开弃牌区）

- 事件卡使用后
- 战斗中被击败的角色
- BP被降至0的角色
- Trigger结算后的生命卡

### 9.4 Removal Area（永久移除区）

- 场地满时移出的卡
- End Phase手牌超限弃掉的卡
- 被效果指定的移除
- **一旦进入，基本无法恢复**

### 9.5 同时发动规则

当多个能力同时发动时：

1. 回合玩家的所有能力优先结算（顺序自选）
2. 非回合玩家的能力随后结算（顺序自选）
3. 结算中产生的新能力插入未结算队列，可选择任意顺序

## 十、规则引擎设计要点

### 10.1 需要建模的核心系统

```
┌──────────────────────────────────────┐
│           Game State Manager          │
│  (统一管理所有区域、资源、状态)         │
└──────────────────────────────────────┘
                    │
    ┌───────┬───────┼───────┬────────┐
    ▼       ▼       ▼       ▼        ▼
┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐
│Turn  ││Phase ││Card  ││Battle││Ability│
│Mgr   ││Mgr   ││Mgr   ││Mgr   ││Queue  │
└──────┘└──────┘└──────┘└──────┘└──────┘
```

### 10.2 关键设计原则

1. **阶段驱动**：游戏进程由阶段状态机严格驱动，每阶段限定可用操作
2. **能力队列**：同时发动的能力进入队列，按规则排序后依次结算
3. **状态可追溯**：所有状态变更需有日志，支持回滚验证
4. **数据与逻辑分离**：卡牌数据（JSON）与规则逻辑（引擎）完全解耦
